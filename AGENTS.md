# canimcp agent instructions

Client source lives in `../../_clients` (the `_clients` folder beside this repo's parent), one blobless clone per client at upstream's default branch, listed in `_clients/repos.tsv`. Read client code there, not from `.inbox/clients/` or any other per-project clone. Run `bash ../../_clients/sync.sh` before reading, cite the commit you read at, and never commit to, branch in, or push from those clones. To build or test a client at a pinned commit, use a `git worktree` of the `_clients` clone, placed outside this repo. A copy with the same instructions sits one level up as `AGENTS.md`, for sessions started in the parent folder. To add a client, add a `name<TAB>upstream-url` line to `repos.tsv` and run the script.

Tool-result handling (which of `content` and `structuredContent` reaches the model) is split with `GitHub/_research/structured-content-research`. That repo holds the `read` tier for it: one note per client at a pinned commit, a daily refresh, and the clients page. canimcp holds the registry, the probe and its `verified` records, and research notes on capabilities other than tool results. Do not write a tool-result research note here; a `read` evidence item for a `tools.result.*` capability points at the note there by commit. The probe's records cite that repo's pins, so a pin bump there means a re-run for any client with an adapter.

Probe work (`probe/`): one agent per client adapter can run in parallel if each touches only `hosts/<client>/` and the shared files (`classify/`, `mock-model/`, `runner.ts`, `lib/`, `registry/*.json`, the schema) have one owner who applies the shared fixes after the reports and then runs `node dist/scripts/reclassify.js` to recompute every record. Use a file-writing tool for TypeScript; Bash heredocs on Windows break on backticks. `probe/README.md` has the platform notes (WSL for fx, Python venvs and timeouts, the hermes worktree); the open follow-ups live in the parent folder's `TODO.md`, outside this repo.
