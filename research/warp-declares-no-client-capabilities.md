# Warp declares no client capabilities, and rmcp still answers roots and elicitation for it

Read at `f8223cef` (2026-11-20) against rmcp 3.5.0, the version `Cargo.lock` resolves.

## What Warp sends

Every connection, stdio, Streamable HTTP and SSE, is served by the value `make_client_info()` returns:

```rust
ClientConfig::new(
    Default::default(),
    Implementation::new(app_id, app_version),
)
```

The first argument is `ClientCapabilities::default()`, whose fields are all `None`. Warp has no type of its own that implements `ClientHandler`. The handler is rmcp's `impl ClientHandler for ClientConfig`, which overrides only `get_info`. So `initialize` and the `server/discover` `_meta` both carry `capabilities: {}`.

## What a server gets if it asks anyway

rmcp 3.5.0's trait defaults answer for Warp:

- `roots/list` returns `Ok(ListRootsResult::default())`, an empty `roots` array, with no error.
- `elicitation/create` returns `action: decline`.
- `sampling/createMessage` returns method not found.
- Every server notification, including the three `list_changed` notifications and `notifications/message`, goes to a no-op.

On a `2026-07-28` connection rmcp first rejects any roots, sampling or elicitation request that is not associated with an in-flight client request (SEP-2260). On `2025-11-25` and older it passes them through to the defaults above.

## The roots finding against rmcp 3.5.0

rmcp does not derive a capability from the presence of a handler. `ClientCapabilities` is a plain struct, and the client sends whatever the `ClientConfig` carries. A roots handler without `roots` in that struct is not advertised, and `roots.listChanged` appears only if the caller sets it. The derivation from a callback is the Python SDK's behaviour, described in `fast-agent-never-sends-roots-list-changed`.

`Peer::notify_roots_list_changed` still exists at `service/client.rs:1753`, generated by the same `method!` macro arm. Warp never calls it. So the goose finding (a removed notification sent on a `2026-07-28` connection) does not reach Warp, for the same reason it does not reach Codex: neither declares roots.

## Compared with the other two rmcp entries

goose declares `roots: {}` and `elicitation: {form: {}}` and implements both. Codex declares elicitation and no roots. Warp declares nothing, and it is the only one of the three whose server would get an empty roots list in place of an error.
